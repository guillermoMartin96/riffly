# Milestone 1 — Audio-to-riff vertical slice

## Goal
In a local browser, record a short monophonic guitar melody, process the actual audio, view time-aligned notes and guitar tab, select a valid time interval, name/save it, reload it, and replay the original audio interval.

## Stack defaults
React + TypeScript + Vite; Python + FastAPI; SQLite for metadata; local media directory. Avoid adding queues, object stores, containers, auth, or external cloud services unless justified.

## Functional scope
- Microphone permission and recording using supported browser APIs; detect supported MIME types and handle failure.
- Session creation, durable original recording, duration, and processing status.
- Pluggable transcription interface returning timestamped MIDI pitches and durations; capture engine/version and failure reason.
- Guitar-tab view with standard tuning E2 A2 D3 G3 B3 E4; plausible string/fret inference with ambiguity disclosed.
- Waveform or timeline with playback cursor; select start/end; save named riff referencing parent recording; list, reload, play and loop saved riff.
- Delete a saved riff without deleting shared source audio; destructive session deletion deferred.
- Clear empty/error states; no false accuracy or real-time inference claims.

## Suggested entities
Session(id, audio_path, audio_mime, duration_seconds, created_at, status)
Transcription(id, session_id, engine, version, status, created_at)
NoteEvent(id, transcription_id, start_seconds, end_seconds, midi_pitch, confidence_nullable, string_nullable, fret_nullable)
Riff(id, session_id, title, start_seconds, end_seconds, created_at)

## Contracts
Note event start >= 0; end > start; intervals are half-open [start,end); source audio clock is canonical. Riff end <= session duration. String/fret must produce same pitch under recorded tuning. Separate detected pitch from chosen fingering. Persist engine provenance and transcription errors.

## Non-goals
Camera analysis, polyphonic chords, standard sheet-music engraving, cloud accounts, collaboration, production-grade streaming transcription, auto-highlights, editing individual notes, and deployment.

## Delivery sequence
A. Scaffold app/API and healthcheck, persistence, test setup.
B. Browser record -> save -> playback, with permission and format handling.
C. Research and benchmark transcription candidates; decision request before production choice.
D. Implement chosen adapter and normalized note events; explicit errors.
E. Tab/time alignment, riff selection, save, reload, replay/loop.
F. Integration/E2E tests, proof evidence, docs, independent review, PR.

## Acceptance
A real recorded monophonic phrase flows end-to-end through an actual inference implementation; the output may be imperfect but must be clearly labeled and measured. Test fixtures alone cannot satisfy this gate. All persisted riff timestamps match playback on reload; tests cover invalid selections, microphone denial, processing failure, and missing audio. All CI checks pass; PR and review evidence available.
